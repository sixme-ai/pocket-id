Pocket ID DevKit local HTTPS profile v1 (Linux x86_64)
Run pocket-id-local-agent-https-v1-linux-amd64.run after verifying its published SHA-256. By default it installs in ~/.local/share/pocket-id-local-agent-https-v1-linux-amd64. To override, supply POCKET_ID_INSTALL_DIR pointing to a new, private absolute path. An existing installation is never migrated. Requires standard GNU/Linux and flock. There is no administrator or system trust-store change.

The issuer is https://localhost:14411. Discovery is /.well-known/openid-configuration. The corresponding introspection URL is https://localhost:14411/api/oidc/introspect. Both the service and the peer transport (14414) bind to IPv4 loopback. The client must check the DNS name localhost and trust explicitly the public CA at <install>/tls/ca.pem. Compare its SHA-256 to the installation owner's public handoff. Every installation gets a distinct CA; never reuse a fingerprint from another installation. The server certificate is valid for one year. Replacement needs explicit new provisioning and binding. The CA signing key is discarded after issuance.

The default resource is http://localhost:18080/mcp and the public PKCE callback is http://localhost:3000/callback. The bootstrap validates discovery and the introspection endpoint before authorizing any local provisioning request. The login link, local OAuth registry and workload/server private keys stay with the installation owner. Share only the public CA, its fingerprint, public client ID and public profile details. Security binds the profile independently.

Stop with <install>/stop.sh. Restart with the identical .run and directory. It retains the original TLS identity and OAuth registration. Another installer build requires a separate directory. Stop the old HTTPS test instance before using the same reserved profile ports in a separate installation. The HTTP DevKit profile has separate ports and directories.
